# Data Breach Notification Template v1

**DRAFT — DO NOT SEND WITHOUT INCIDENT AUTHORITY / LEGAL REVIEW WHERE
REQUIRED.**

This is a **drafting template only**, for use once
`docs/australian-incident-ndb-procedure-v1.md`'s assessment (Sections
11–18) has actually concluded that notification is required — never
before. It does not fill in any entity name, ABN, registered office,
privacy officer, or legal-counsel details on Tether's behalf: those do
not yet exist for Tether as of this pass, and must be supplied from the
actual, confirmed entity details at the time this template is used —
never invented, never carried forward from a placeholder.

**This template contains no automatic admission of liability.** The
description fields below are for a factual account of what happened —
not an assignment of fault, and not a legal characterisation of the
incident beyond what has actually been determined.

This template may be used for OAIC notification content, individual
notification content, or both — the two audiences need different framing
even when the underlying facts are the same; draft each separately using
the same source facts from `docs/data-breach-assessment-record-v1.md`.

## Notes for whoever drafts this

- Pull every factual claim from the completed (or in-progress, if
  urgency requires drafting before the assessment fully closes)
  assessment record — do not introduce new facts here that aren't
  already in that record.
- State only what is actually known; where something is still being
  investigated, say so rather than omitting it or guessing.
- Recommended steps should be genuinely actionable for the recipient —
  not generic boilerplate unrelated to the actual information exposed.
- Before sending: confirm notification decision authority (procedure
  Section 7) has approved this specific draft, and that legal review has
  occurred where the incident's specifics warrant it (e.g. any case
  where NDB applicability, eligible-breach status, or entity identity
  is not already fully settled).
